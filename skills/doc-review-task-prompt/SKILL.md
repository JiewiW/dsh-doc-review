# doc-review-task-prompt 任务执行 prompt 审查

## 领域背景

本技能面向「任务执行 prompt」的独立发布前审查：目标文档是发给执行 Agent（可能在独立子会话、独立上下文窗口中执行）的任务卡/派活 prompt，而不是写给人读的说明文。审查员是「找茬者」角色：假设自己对发起会话一无所知、只读这一份 prompt 就要开工，默认质疑每一条指令的可执行性与可验收性。

任务执行 prompt 的失败模式与普通文档不同：事实错误尚在其次，更致命的是「执行者开不了工」（缺目标/缺工作区/依赖会话记忆）、「干完无法判定对错」（验收靠主观感觉）、「分支没写尽导致误操作」、「有依赖的步骤被并发执行」、「踩了权限红线」。因此判据以 DSH 任务卡片规范 TB-C5（十一项最低覆盖）与技能 llm-doc-writing-standard（R1–R55）为来源，结构化为 D1–D11 规则。

输出仍使用 doc_review 既有报告 Schema（summary/issues[id,dimension,severity,location,claim,evidence,suggestion]/newIssueCount）。dimension 为闭合四枚举（fact/completeness/necessity/format），D1–D11 按下表归并，**规则编号必须写进 claim 与 id**，禁止私造第五个 dimension：

| 规则 | 归并 dimension | 规则 | 归并 dimension |
| --- | --- | --- | --- |
| D1 自足性 | completeness（夹带无据事实时兼 fact） | D7 顺序语义 | completeness |
| D2 验收信号客观性 | completeness | D8 投递闭合 | completeness |
| D3 分支穷尽兜底 | completeness | D9 权限红线 | completeness |
| D4 量纲口径 | completeness | D10 TB-C5 覆盖 | completeness |
| D5 产物样例 | completeness | D11 必要性 | necessity |
| D6 术语事实标签 | fact | 纯 markdown 结构破损 | format |

id 形如 `TP-C-01`（TP=task-prompt，C=completeness/F=fact/N=necessity/FT=format，序号两位）。claim 必须以规则编号开头，如 `[D2] 第三步验收信号不客观`。同一规则可命中多条 issue，序号顺延。

边界：只审查 prompt 文本本身的可执行性，不替作者重新设计任务，不评价任务的业务价值；prompt 中明确标注【待核实】的事实不得当作既成事实挑错，但要检查它是否被误当成推理前提。

## 审查规则

### 判定纪律（所有规则共用，先于 D1–D11 执行）

- 定位必须是 prompt 原文：每条 issue 的 location 填 ≥8 个连续字符的原文引句（须在目标 prompt 中逐字命中）或某个 markdown 标题行原文；缺失项类问题（文本里根本不存在的要素）location 填该缺失项所属步骤/小节的标题行原文，claim 中说明「该小节缺少什么」。
- severity 三档：high=不修订就不得放行（执行者会开不了工、无法判收、误操作或越权）；medium=可开工但显著增加返工/沟通成本；low=不影响执行的瑕疵。
- evidence：prompt 之外无参考资料时一律填 `no-reference`，禁止编造出处。

### D1 自足性（severity=high，dimension=completeness）

- 做法：把目标 prompt 当成与发起会话零共享的独立文本来读，核对①用户原始目标/原话是否在文内自包含；②工作区根（绝对路径或可定位锚点）是否写明；③每个代词、指代、「该文件/上述方案」能否在文内找到先行词。
- 触发条件：目标只存在于会话记忆（如「按刚才说的改」「继续上一卡」）而文内无重述；缺工作区路径；关键输入只有文件名无路径且无工作区锚点。
- 后果：执行者脱离会话无法开工或猜错对象，severity=high。若 prompt 把会话中的传闻当成事实写入（无来源断言），兼按 fact 出 issue。

### D2 验收信号客观性（severity=high，dimension=completeness）

- 做法：逐步检查每个执行步骤是否给出可运行命令与客观正信号——退出码、产物文件路径（可读回校验）、日志/输出中的特征字符串、可 grep 的编号或计数；验收必须是执行者跑完就能判定真假的命题。
- 触发条件：出现「确保正确」「自测通过」「看起来正常」「用户满意即可」「检查一下没问题」等主观表述而无命令与正信号；有命令但无成功判据（未说退出码几、产物在哪、日志出现哪行算过）。
- 后果：完工标准不可机检，交付闭合失效，severity=high。负信号同样要客观（如「日志中 Cannot find module 出现 0 次」）。

### D3 分支穷尽与兜底（severity=medium；遗漏分支可能导致误操作时升 high，dimension=completeness）

- 做法：对每个条件分支核对 if/else 是否写尽、失败路径是否给重试次数与上限、重试耗尽后换什么办法、何时停下来上报用户。
- 触发条件：只写成功路径；「失败重试」无次数/无换法出口；条件枚举不穷尽且无 otherwise 兜底；失败后的清理/回滚动作缺失可能留下脏状态。
- 后果：执行者在异常分支自由发挥即可能误操作（删错、覆盖、卡死等待），此时 severity=high；仅增加返工的 severity=medium。

### D4 量纲与口径（severity=medium，dimension=completeness）

- 做法：核对所有阈值、数字、单位与统计口径是否写死——字符/词/码点、空白与换行处理、百分比保留位、长度上限、超时秒数；魔法数字须带来源或标签。
- 触发条件：出现「大文件」「较多」「适当」「大约几十个」等量词无口径；同一数字两处口径不一（如一处按 token 一处按字符）；阈值无出处。
- 后果：执行者与验收者口径漂移，结果不可复现，severity=medium。

### D5 产物与样例（severity=medium，dimension=completeness）

- 做法：核对交付物路径是否明确（绝对路径或相对工作区根，目录/文件名可直接创建）；结构化产物（JSON/表格/报告）是否给出样例或字段模板；新建文件与修改既有文件是否区分。
- 触发条件：只说「输出一份报告」无路径无格式；路径含未定义变量；要求 JSON 但无字段清单；要求「改配置」但未指明文件。
- 后果：产物落不到下游可读位置，severity=medium；下游卡片因此无法读取时升 high。

### D6 术语与事实标签（severity=low；被当成前提时 medium，dimension=fact）

- 做法：核对同一概念前后命名一致（枚举值、文件名、服务名不得中途换写法）；未核实事实是否带【待核实】标签，且标签项不得作为其他步骤的既定前提。
- 触发条件：同一对象出现两种叫法且无声明；把推测写成事实（「该接口返回 X」未经核实）；【待核实】项被后续步骤无条件依赖。
- 后果：术语漂移导致找错对象 severity=low；未核实事实当前提会连锁误导，severity=medium。

### D7 顺序语义（severity=high，dimension=completeness）

- 做法：核对有依赖的步骤是否写明先后与交接物（上一步产出的哪个文件/字段是下一步输入）；可并发步骤是否显式标注并行/串行并说明互不共享写集；多卡链是否带 `【k/N】`、chain/seq 标签或前置卡引用（卡片 id/标题）；前置卡未完成是否禁止开工及如何核对（如 task_board_get 核对 result=succeeded）。
- 触发条件：步骤间有数据/状态依赖却用并列罗列，未标先后；该串行的步骤被拆成会并发启动的子任务；引用「上一卡」但无卡 id 或产物路径；前置门禁无核对动作。
- 后果：并发踩踏、读到旧产物或在前置未完成时开工，severity=high。

### D8 投递闭合（severity=medium，dimension=completeness）

- 做法：核对完成后向谁/在哪里回报（卡片评论、最终回复、看板状态流转）、产物如何被下一张卡或调用方读取（文件路径交接而非会话记忆）、最终回复必须包含哪些要素是否逐项列明。
- 触发条件：只说「做完即可」无回报对象；产物停留在会话输出里未落盘；最终回复无必含清单；卡片状态如何置 done/failed 未写。
- 后果：任务结果无法被消费、状态悬空，severity=medium；整条链因此断裂时 high。

### D9 权限与红线（severity=high，dimension=completeness）

- 做法：核对权限是否最小化并钉死（工作区 id、只读/工作区写/全访问预设、是否需要人审）；明确列出禁止触碰项（端口、profile、生产配置、特定目录）；危险命令（删除、强杀、发布、push、publish）是否有显式禁令或精确 PID/精确路径约束。
- 触发条件：要权限却不说明用途；存在「清理环境」类无界指令；允许通配批量杀进程；允许改生产/他人正在用的实例；发布类动作无「禁止公开」开关。
- 后果：越权或破坏性操作风险，severity=high，且不接受「执行者会小心」类缓解。

### D10 TB-C5 覆盖（severity=high，dimension=completeness）

- 做法：用文末「TB-C5 十一项自查清单」逐项机检 prompt，每一项必须能在文中指出对应段落或显式标注「本任务不适用」及理由；缺项即 issue，一条缺项一个 issue，location 取最接近的小节标题行，claim 以 `[D10][C5-n]` 双编号开头。
- 触发条件：十一项中任一项无对应文本且无显式不适用声明；清单要素只存在于隐含语义中（执行者需推断才算）。
- 后果：任务卡不满足最低契约，severity=high。注意：D10 管「有没有」，D1–D9 管「写得够不够好」，同一缺项可同时命中 D10 与专项规则（各出一条 issue）。

### D11 必要性（severity=low，dimension=necessity）

- 做法：对每个步骤/产物做删除测试——不做它，总目标是否仍达成；防分解膨胀（把一件事拆成多卡/多步刷产出）。该规则默认低优先，仅在 prompt 明确要求精简或出现明显冗余步骤时出 issue。
- 触发条件：步骤与总目标无服务关系；两份产物内容重复；为拆而拆的子任务。
- 后果：severity=low；不确定时不出 issue（必要性判断让位于可执行性）。

### TB-C5 十一项自查清单（D10 逐项机检依据；锚点 C5-1～C5-11）

| 锚点 | TB-C5 项 | 文中存在的机检信号（看到什么算有） | 关联规则 |
| --- | --- | --- | --- |
| <a id="c5-1"></a>C5-1 自包含目标 | 目标/用户原话在文内 | 有目标小节，含动词开头的交付物与用户原话或原意重述，不依赖会话历史 | D1 |
| <a id="c5-2"></a>C5-2 工作区 | 工作区定位 | 出现工作区绝对路径或可定位锚点（如 `D:\\...`、workspaceId），权限预设钉死 | D1、D9 |
| <a id="c5-3"></a>C5-3 输入 | 输入物清单 | 列出要读的文件/卡/数据及路径或获取方式，代词均有先行词 | D1、D5 |
| <a id="c5-4"></a>C5-4 产物及路径 | 交付物+落点 | 每份产物有文件名与目录路径，结构化产物有字段模板或样例 | D5 |
| <a id="c5-5"></a>C5-5 执行步骤 | 有序步骤 | 编号步骤，依赖步骤标先后与交接物，并发步骤标「并行」且写集不相交 | D7 |
| <a id="c5-6"></a>C5-6 每步命令 | 命令可直接运行 | 每个需执行的动作给出完整命令行/工具调用名与参数，不写「运行相关命令」 | D2、D3 |
| <a id="c5-7"></a>C5-7 验收 | 客观正信号 | 每步/总验收有退出码、产物可读回路径或日志特征串，无「看起来对」类主观判据 | D2 |
| <a id="c5-8"></a>C5-8 边界 | 范围边界 | 写明做什么/不做什么，只允许改动的目录或文件范围 | D9、D11 |
| <a id="c5-9"></a>C5-9 不得碰 | 禁令清单 | 显式列出禁碰端口/实例/profile/目录与禁做动作（push、publish、通配杀进程等） | D9 |
| <a id="c5-10"></a>C5-10 上下文交接 | 跨卡/跨会话交接 | 前置依赖落成文件路径或卡片 id（含 result 核对动作），产出说明下一张卡读哪个路径 | D7、D8 |
| <a id="c5-11"></a>C5-11 引用路径 | 引用可追溯 | 引用的文档/代码/命令带完整路径，未核实信息带【待核实】标签且未当前提 | D5、D6 |

机检纪律：任一项找不到机检信号时，先全文再搜一遍同义段落；确认缺失才出 issue，禁止凭印象判缺。标注「不适用」的项必须在文中给出理由（如纯分析任务无产物时显式声明），无理由的不适用声明按缺项处理。
